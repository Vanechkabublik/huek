# Авито-клон — доска объявлений на PHP + Docker

Монолитное веб-приложение: чистый **PHP 8.2 (ООП) + PDO/PostgreSQL 16**, нативные HTML/CSS/JS (AJAX через `fetch`).
Без фреймворков и Composer-пакетов. Дизайн — в духе современного Авито: синий + жёлтый акценты, шрифт Inter,
карточки с тенями и hover-анимациями, адаптив от 360 px до широких мониторов.

## Быстрый старт

```bash
cd avito-clone
docker compose up -d --build        # первый запуск: скачивание образов (Alpine+PHP ~30 МБ, postgres:16) и инициализация БД
```

Откройте **http://localhost:8080**.

| Что                 | Адрес / доступ                                                             |
|---------------------|----------------------------------------------------------------------------|
| Сайт                | http://localhost:8080                                                      |
| Админ-панель        | http://localhost:8080/admin.php — `admin@example.com` / `admin123`         |
| Пользователь 1      | `ivan@example.com` / `user123` (Иван Петров, Москва)                        |
| Пользователь 2      | `maria@example.com` / `user123` (Мария Соколова, Санкт-Петербург)           |
| Adminer (опц.)      | `docker compose --profile tools up -d` → http://localhost:8081 (система `PostgreSQL`, сервер `db`, пользователь/пароль/БД: `ads_user` / `ads_pass` / `ads`) |

На странице входа есть кнопки быстрого входа «Админ / Иван / Мария» (только в демо-режиме `APP_DEMO=1`).

**Выложить сайт в интернет с HTTPS** (свой поддомен + сервер с Docker) — см. [DEPLOY.md](DEPLOY.md).

Полезные команды:

```bash
docker compose logs -f app          # логи Apache/PHP
docker compose down                 # остановить (данные БД сохраняются в томе pg_data)
docker compose down -v              # остановить и стереть БД — при следующем старте заново выполнятся docker/init/*.sql (нужно после правок схемы/сида)
cp .env.example .env                # поменять порты/пароли (все переменные имеют значения по умолчанию)
```

> Папка `public/uploads` (фото) монтируется с хоста вместе с проектом, поэтому фото переживают пересборку контейнера.
>
> **Образ PHP.** По умолчанию — Alpine + PHP 8.3 из пакетов и встроенный сервер `php -S` (8 процессов, `docker/php/router.php`):
> образ скачивается за секунды даже на медленном канале. Он рассчитан на демо и разработку. Для боевого режима
> переключитесь на Apache: в `docker-compose.yml` замените `dockerfile:` на `docker/php/apache/Dockerfile` (образ `php:8.2-apache`, ~500 МБ).
>
> **Медленный Docker Hub.** Docker Desktop → Settings → Docker Engine → добавьте `"registry-mirrors": ["https://mirror.gcr.io"]`.
> Файлы `seed_*.svg` в ней — демо-картинки для тестовых объявлений, не удаляйте их.

## Что умеет приложение

**Посетитель**
- Лента объявлений: карточки 4/3/2/1 колонки, бейджи «Хит» и число фото, скелетоны загрузки, «Показать ещё».
- Живой поиск в шапке (debounce 300 мс), фильтры: город, категория, цена от/до, сортировка; состояние хранится в URL.
- Полоса категорий с иконками под шапкой (на мобильных скроллится); фильтры на мобильных — нижняя шторка.
- Страница объявления: галерея (стрелки, миниатюры, свайп на телефоне, полноэкранный просмотр), «Показать телефон»
  (AJAX), «Написать сообщение», «Поделиться», карточка продавца, «Все объявления продавца», похожие объявления.

**Пользователь**
- Регистрация / вход, создание и редактирование объявления на одной странице: inline-валидация, счётчики символов,
  drag&drop-загрузка фото с превью и удалением (1–10 фото), после отправки — «Объявление отправлено на модерацию».
- «Мои объявления»: табы Все / На модерации / Одобрены / Отклонены / Заблокированы со счётчиками, причина
  отказа/блокировки от администратора, «Редактировать» (возвращает на модерацию) и «Удалить».
- «Сообщения»: входящие/отправленные, ответ покупателю.

**Администратор** (`/admin.php`, тёмный sidebar)
- **Статистика**: пользователи, объявления, на модерации, заблокировано (+ одобрено, отклонено, категорий); плитки — ссылки.
- **Пользователи**: мгновенный поиск по email; просмотр объявлений пользователя, смена пароля (модалка),
  блокировка/разблокировка (блокированный пользователь теряет сессию сразу, его объявления пропадают из ленты),
  удаление пользователя вместе с объявлениями и файлами.
- **Объявления**: табы по статусам, таблица с цветными бейджами, «Одобрить», «Отклонить» и «Заблокировать» (модалка
  с обязательной причиной — автор увидит её в «Моих объявлениях»).
- **Категории**: добавление, inline-редактирование названия и эмодзи-иконки, удаление с предупреждением
  (объявления из удалённой категории не пропадают — остаются «без категории»).

Администраторов нельзя блокировать, удалять и менять им пароль через панель; себя — тем более.

## API (все ответы — JSON `{"ok": true, …}` или `{"ok": false, "error": "…", "errors": {"поле": "…"}}`)

| Эндпоинт           | Действия (`?action=`)                                                                                  |
|--------------------|--------------------------------------------------------------------------------------------------------|
| `api/auth.php`     | `login`, `register`, `logout` (POST) · `me` (GET)                                                      |
| `api/ads.php`      | `list` (q, category, city, price_min, price_max, sort, user, page) · `meta` · `mine` — GET; `phone`, `create`, `update`, `delete` — POST |
| `api/upload.php`   | `upload` (multipart `file`), `delete` (убрать превью до сохранения) — POST                              |
| `api/messages.php` | `send` (POST) · `inbox` (GET, `box=in\|sent`)                                                          |
| `api/admin.php`    | GET: `stats`, `users`, `ads`, `categories` · POST: `user_block`, `user_unblock`, `user_password`, `user_delete`, `ad_moderate`, `category_create`, `category_update`, `category_delete` |

Коды: `401` — нужен вход, `403` — нет прав, `404` — не найдено, `419` — устарел CSRF-токен, `422` — ошибки валидации по полям.

## Безопасность

- **SQL**: только PDO prepared statements (`ATTR_EMULATE_PREPARES = false`), `LIKE`/`ILIKE` экранируется, `ORDER BY` — по белому списку.
- **Пароли**: `password_hash` / `password_verify`, автоматический rehash; время ответа при неверном email выровнено.
- **Сессии**: `HttpOnly`, `SameSite=Lax`, `use_strict_mode`, `session_regenerate_id` при входе. Пользователь перечитывается из БД
  на каждый запрос — блокировка действует мгновенно.
- **CSRF**: токен в сессии → `<meta name="csrf-token">` → заголовок `X-CSRF-Token` на всех POST (`Csrf::verify`).
- **Права**: проверка на каждом эндпоинте (`Auth::requireLogin`, `Auth::requireAdmin`); владение объявлением проверяется в `Ad`.
- **Загрузки**: MIME по содержимому (`finfo`) + `getimagesize`, лимит 5 МБ и 25 Мп, белый список JPG/PNG/WEBP/GIF, расширение
  выбирает сервер; файл перекодируется через GD (вычищает EXIF и «приклеенный» код), имя — случайное. К объявлению можно привязать
  только фото, загруженное в текущей сессии. В `uploads/` Apache не исполняет PHP.
- **XSS**: серверные шаблоны — `htmlspecialchars` (`e()`), клиентский JS строит DOM через `createElement`/`textContent`, `innerHTML` не используется.
- DocumentRoot — `public/`: `src/`, `templates/`, `docker/` и `.env` недоступны по HTTP. `docker/php/router.php` (встроенный сервер)
  и `docker/php/apache/vhost.conf` (Apache) закрывают скрытые файлы и запрещают исполнять PHP в `uploads/`.

## Дизайн-система (`public/assets/css/style.css`)

- Палитра: синий `#00AAFF` (кнопки, ссылки, активные состояния), жёлтый `#FFC700` (бейдж «Хит», «На модерации», активный
  таб, кнопка «Написать сообщение»), текст `#1A1A1A`, серый `#767676`, успех `#00C853`, ошибка `#FF3B30`, предупреждение `#FF9500`.
- Шрифт **Inter** (Google Fonts) с системным fallback; иконки — свой SVG-спрайт в стиле Feather/Lucide (работает без CDN).
- Радиусы: карточки 12 px, кнопки 8 px, pill-элементы 20 px; тени карточек `0 2px 8px rgba(0,0,0,.08)`, hover — подъём на 2 px.
- Состояния кнопок: hover (темнее), active (нажата), disabled (полупрозрачная), loading (спиннер).
- Тосты сверху справа (успех — зелёный, ошибка — красный, модерация — жёлтый, исчезают через 3 с), модалки с overlay и blur.

## Запуск без Docker (для разработки)

Нужны PHP ≥ 8.2 с `pdo_pgsql`, `gd`, `mbstring`, `fileinfo`, `exif` и PostgreSQL 12+ (локаль БД с поддержкой кириллицы, например `en_US.UTF-8`, — иначе регистронезависимый поиск `ILIKE` не будет учитывать регистр русских букв).

```bash
psql -U postgres -c "CREATE USER ads_user WITH PASSWORD 'ads_pass'" -c "CREATE DATABASE ads OWNER ads_user"
PGPASSWORD=ads_pass psql -h 127.0.0.1 -U ads_user -d ads -f docker/init/01-schema.sql -f docker/init/02-seed.sql
DB_HOST=127.0.0.1 APP_DEBUG=1 APP_DEMO=1 php -S 127.0.0.1:8080 -t public docker/php/router.php
```

## Что проверено

Код прогнан вручную в браузере (Chromium/Playwright) на PostgreSQL 16 и PHP 8.3: поиск и фильтры, «Показать ещё», галерея,
регистрация, загрузка и удаление фото, создание/редактирование объявления, модерация с причиной, блокировка пользователя
(сессия умирает сразу, объявления скрываются), смена пароля, CRUD категорий, права доступа, CSRF, попытки загрузить не-изображение,
подмену чужого файла и XSS в заголовке. Сборка Docker-образов в среде разработки не запускалась — `docker compose config` проходит,
но первый `docker compose up --build` на вашей машине — это первая реальная сборка.

## Ограничения и что можно улучшить

- Нет защиты от перебора паролей (rate limiting) и капчи при показе телефона.
- Фото, загруженные, но так и не привязанные к объявлению (вкладку закрыли), остаются на диске — нужен cron-скрипт очистки.
- Нет восстановления пароля по email и подтверждения email (письма не отправляются).
- Поиск — `ILIKE`; для больших объёмов стоит добавить полнотекстовый индекс (`tsvector` + GIN).
- Нет избранного и истории диалогов «цепочкой»: сообщения показаны плоским списком.
