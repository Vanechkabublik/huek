# Авито-клон — доска объявлений на PHP + Docker

Монолитное веб-приложение: чистый **PHP 8.2+ (ООП) + PDO/PostgreSQL 16**, нативные HTML/CSS/JS (AJAX через `fetch`) и свой
**WebSocket-сервер на PHP** для чата. Без фреймворков и Composer-пакетов. Дизайн — сдержанный и деловой: шрифт **Montserrat**
(лежит на сервере, внешние CDN не нужны), спокойная сине-графитовая палитра, линейные SVG-иконки вместо эмодзи, собственный логотип и
набор favicon/ico/PWA-иконок, **светлая и тёмная темы**, адаптив от 360 px до широких мониторов.

## Быстрый старт

```bash
cd avito-clone
docker compose up -d --build        # первый запуск: образы (Alpine+PHP ~30 МБ, postgres:16), миграции БД и демо-данные
```

Откройте **http://localhost:8080**.

| Что                 | Адрес / доступ                                                             |
|---------------------|----------------------------------------------------------------------------|
| Сайт                | http://localhost:8080                                                      |
| Админ-панель        | http://localhost:8080/admin.php — `admin@example.com` / `admin123`         |
| Пользователь 1      | `ivan@example.com` / `user123` (Иван Петров, Москва)                        |
| Пользователь 2      | `maria@example.com` / `user123` (Мария Соколова, Санкт-Петербург)           |
| WebSocket чата      | `ws://localhost:8081` (браузер подключается сам)                            |
| Adminer (опц.)      | `docker compose --profile tools up -d` → http://localhost:8082 (система `PostgreSQL`, сервер `db`, пользователь/пароль/БД: `ads_user` / `ads_pass` / `ads`) |

На странице входа есть кнопки быстрого входа «Админ / Иван / Мария» (только в демо-режиме `APP_DEMO=1`).
Чтобы увидеть чат в реальном времени, откройте сайт в двух браузерах (или обычном и приватном окне) под Иваном и Марией.

**Выложить сайт в интернет с HTTPS** (свой поддомен + сервер с Docker) — см. [DEPLOY.md](DEPLOY.md).
**Подключить вход через Яндекс и Google** (где взять ключи и что куда вписать) — см. [docs/OAUTH_LOGIN.md](docs/OAUTH_LOGIN.md).

Полезные команды:

```bash
docker compose logs -f app          # логи сайта
docker compose logs -f ws           # логи WebSocket-сервера
docker compose down                 # остановить (данные БД сохраняются в томе pg_data)
docker compose down -v              # остановить и стереть БД — при следующем старте миграции и демо-данные зальются заново
cp .env.example .env                # поменять порты/пароли/ключи (все переменные имеют значения по умолчанию)
```

> Папка `public/uploads` (фото, аватары) монтируется с хоста вместе с проектом, поэтому файлы переживают пересборку контейнера.
> Файлы `seed_*.svg` в ней — демо-картинки для тестовых объявлений, не удаляйте их.
>
> **Образ PHP.** По умолчанию — Alpine + PHP 8.3 из пакетов и встроенный сервер `php -S` (8 процессов, `docker/php/router.php`):
> образ скачивается за секунды даже на медленном канале. Для серьёзной нагрузки переключитесь на Apache: в compose-файле замените
> `dockerfile:` на `docker/php/apache/Dockerfile` (образ `php:8.2-apache`, ~500 МБ).
>
> **Медленный Docker Hub.** Docker Desktop → Settings → Docker Engine → добавьте `"registry-mirrors": ["https://mirror.gcr.io"]`.

## Что умеет приложение

**Посетитель**
- Лента объявлений: карточки 4/3/2/1 колонки, бейджи «Хит» и число фото, скелетоны загрузки, «Показать ещё».
- Живой поиск в шапке (debounce 300 мс), фильтры: город, категория, цена, **характеристики категории**, сортировка;
  состояние хранится в URL. На карточке — строка характеристик (например, «Toyota · 2018 · 64 000 км»).
- Страница объявления: галерея (стрелки, миниатюры, свайп, полноэкранный просмотр), блок характеристик, «Показать телефон»,
  «Написать сообщение», «Поделиться», карточка продавца с рейтингом, похожие объявления.
- **Профиль продавца** (`/seller.php?id=…`): аватар, «о себе», рейтинг и число отзывов, активные объявления и вкладка «Отзывы».
- **Тёмная тема**: переключатель в шапке и в админке, выбор запоминается; без выбора берётся системная тема, без мигания при загрузке.
- **Город «как на Авито»**: при первом заходе браузер по кнопке «Определить» запрашивает геолокацию, сервер превращает координаты в город
  (OpenStreetMap Nominatim, результат кэшируется), город запоминается в cookie и в профиле, лента фильтруется по нему; кнопка города в шапке
  открывает выбор вручную (подсказки, «Все города»). Работает по `https://` и только с разрешения пользователя.
- **Страницы документов**: `/privacy.php` (политика обработки персональных данных) и `/terms.php` (пользовательское соглашение).

**Пользователь**
- Регистрация по email или **вход через Яндекс и Google** (OAuth 2.0 + PKCE; кнопка провайдера появляется, когда для него заданы ключи).
- **Согласие с политикой и соглашением** обязательно при регистрации и любом входе (email, Яндекс, Google): галочка со ссылками на документы,
  время и версия согласия сохраняются в профиле пользователя.
- Создание и редактирование объявления: inline-валидация, drag&drop-фото (1–10), **поля характеристик под выбранную категорию**
  (авто — марка, модель, год, пробег, коробка, топливо, кузов; электроника — тип, бренд, состояние, гарантия, память…), **подсказки городов**
  (клавиатура ↑↓ Enter Esc; 298 городов офлайн + города из существующих объявлений; кнопка «Определить автоматически»),
  **предпочтительный способ связи** (звонок и сообщения / только сообщения — телефон скрыт / только звонок — чат для объявления выключен;
  плюс «удобное время для связи») и **видеообзор** — отдельный необязательный пункт в самом конце формы, после фотографий
  (MP4, MOV, WebM до 50 МБ и 3 минут; на странице объявления видео — последний слайд галереи).
- «Мои объявления» с модерацией/причинами отказа, **статистика объявления** (`/ad-stats.php?id=…`): уникальные просмотры, избранное,
  показанные телефоны, диалоги, график за 14 дней.
- **Избранное** (сердечко на карточке и странице объявления, список `/favorites.php`).
- **Чат цепочками** (`/chat.php`): диалог = объявление + покупатель; список диалогов со счётчиками, двухпанельный интерфейс
  (на телефоне — список → переписка); у своих сообщений статусы **«Не прочитано» / «Прочитано»** (одна/две галочки, время прочтения в подсказке);
  «печатает…», счётчик непрочитанных в шапке, нижней навигации и в заголовке вкладки, всплывающее уведомление о новом сообщении.
- **Звонки голосом и видео** прямо с сайта (WebRTC): кнопки в чате и на странице объявления, микрофон и камера включаются/выключаются в любой момент,
  в углу окна — значок с **пингом** и подробностями связи, входящий вызов виден на любой странице, окно можно свернуть; итог звонка попадает в переписку
  («Исходящий звонок · 2:31», «Пропущенный звонок»). Если прямое соединение невозможно, звук и видео идут через TURN-сервер coturn. Подробнее — [docs/CALLS.md](docs/CALLS.md).
- **Отзывы** о продавце (1–5 звёзд + текст): оставить может тот, кто переписывался с продавцом в чате (защита от накрутки), один отзыв на продавца — повторная отправка обновляет его.
- Профиль (`/profile.php`): имя, email, телефон, **город**, «о себе», аватар (перекодируется в 256×256), смена пароля, привязка/отвязка аккаунтов Яндекса и Google.

**Реальный IP и User-Agent.** При регистрации и каждом входе сохраняются IP-адрес (с учётом прокси: `X-Forwarded-For` принимается только от доверенных
прокси, подделка заголовка не работает), браузер/ОС/тип устройства и согласие. Данные видны администратору в карточке пользователя и в разделе «Безопасность»
(журнал входов, неудачные попытки, устройства, аккаунты с одного IP) — для аналитики и защиты от злоупотреблений.

**Баны.** Аккаунт можно заблокировать **с обязательной причиной и сроком** (навсегда / 1, 7, 30 дней / до даты), при желании вместе с IP-адресами пользователя
(адреса администраторов и ваш собственный не банятся). Заблокированный человек при попытке входа **любым способом** (email, Яндекс, Google) видит причину и срок,
а действующая сессия обрывается сразу. Отдельно можно забанить **IP-адрес или сеть (CIDR)**: на вход и регистрацию либо на весь сайт; бан тоже имеет причину и срок, истёкшие
баны снимаются автоматически.

**Счётчик просмотров — считаем людей, а не загрузки страницы.** Один человек = один просмотр объявления: гость определяется cookie `vid`
(живёт год), вошедший — id пользователя. Обновление страницы, повторные заходы, переход гость → вход не увеличивают счётчик; не учитываются
автор, администраторы, боты и превью ссылок (по User-Agent и заголовкам prefetch). Хранится в таблице `ad_views (ad_id, viewer_key)` с уникальным ключом,
поэтому гонки запросов тоже не накручивают значение.

**Чат в реальном времени.** Свой WebSocket-сервер (`bin/ws-server.php`, чистый PHP по RFC 6455, без библиотек). Приложение пишет сообщение в БД и
шлёт событие через PostgreSQL `NOTIFY`; WS-сервер слушает канал и доставляет событие участникам диалога. Браузер подключается по подписанному
короткоживущему тикету (HMAC, `APP_SECRET`), проверяется Origin. Если WebSocket недоступен — страница показывает баннер и подтягивает
сообщения опросом раз в 5 секунд, а при возврате соединения переподключается сама.

**Администратор** (`/admin.php`, тёмный sidebar, переключатель темы)
- **Дашборд**: плитки, графики за 14 дней (новые пользователи/объявления, сообщения в чате), очередь модерации с быстрым «Одобрить», топ категорий, последние действия.
- **Пользователи**: поиск по email/имени/телефону/#id, фильтры (активные, заблокированные, админы, вошедшие через Яндекс/Google), карточка пользователя
  с активностью и историей действий, смена роли, блокировка/разблокировка, смена пароля, удаление.
- **Объявления**: вкладки по статусам со счётчиками, поиск, фильтры по категории и сортировка, карточка объявления (фото, характеристики, статистика, история модерации),
  одобрить / отклонить / заблокировать с причиной, **массовые действия** над отмеченными, удаление.
- **Категории и характеристики**: CRUD категорий и **редактор полей** (текст, число с единицей и диапазоном, список вариантов, обязательность, участие в фильтрах) — новое поле сразу появляется в форме объявления и фильтрах.
- **Отзывы**: просмотр и удаление. **Журнал действий** (кто, что и когда менял). **Экспорт CSV** пользователей и объявлений (для Excel, с BOM и `;`).
- **Безопасность**: журнал входов (регистрации, входы, неудачные попытки, блокировки) с IP и устройством, баны по IP/подсети (причина, срок, область — вход или весь сайт),
  статистика устройств и «подозрительные» IP с несколькими аккаунтами.
- **Документы**: редактор политики обработки данных и пользовательского соглашения (простая разметка: `# Заголовок`, `- пункт списка`, абзацы; подстановки
  `{{site}}`, `{{operator}}`, `{{email}}`, `{{date}}` — реквизиты вписываются во вкладке «Название и контакты»; версия согласия растёт при каждом изменении). Тексты — шаблоны: впишите реквизиты и проверьте их с юристом.
- **Блокировка** пользователя — с обязательной причиной, сроком и (по желанию) баном его IP; карточка пользователя показывает причину, срок и кто заблокировал.
- **Интеграции**: статус входа через Яндекс и Google с готовыми значениями для их кабинетов (Redirect URI, домен) и пошаговой инструкцией,
  статус WebSocket, предупреждения об открытом демо-режиме/отладке.

Администраторов нельзя блокировать и удалять через панель; себя — тем более.

## Миграции БД

Схема лежит в `database/migrations/*.sql` и применяется автоматически при старте контейнера `app` (`bin/migrate.php`): уже применённые
файлы пропускаются (таблица `schema_migrations`), параллельный запуск защищён advisory-блокировкой. База от предыдущей версии проекта
распознаётся и дообновляется без потери данных (старые сообщения переносятся в новый чат). Новая миграция — это новый файл
`004_что_делает.sql`; файлы уже выпущенных миграций не редактируются.

## API (все ответы — JSON `{"ok": true, …}` или `{"ok": false, "error": "…", "errors": {"поле": "…"}}`)

| Эндпоинт              | Действия (`?action=`)                                                                                 |
|-----------------------|-------------------------------------------------------------------------------------------------------|
| `api/auth.php`        | `login`, `register` (нужно `consent=1`), `logout` (POST) · `me` (GET)                                  |
| `api/listings.php`    | GET: `list` (q, category, city, price_min/max, `a_<код>`, `a_<код>_min/_max`, sort, user, page), `meta`, `mine`, `stats` · POST: `phone`, `create`, `update`, `delete` |
| `api/favorites.php`   | `list` (GET) · `toggle` (POST)                                                                        |
| `api/profile.php`     | POST: `update`, `avatar`, `avatar_delete`, `password`, `identity_unlink`                              |
| `api/reviews.php`     | GET: `list`, `can` · POST: `save`, `delete`                                                           |
| `api/chat.php`        | GET: `list`, `thread`, `ticket`, `unread`, `ice` (STUN/TURN для звонков) · POST: `send`, `read`        |
| `api/upload.php`      | `upload` (фото), `video` (видеообзор, multipart `file`), `delete` (убрать превью до сохранения) — POST |
| `api/geo.php`         | `resolve` (POST: lat, lon → город) · `set` (POST: выбрать город / «все города») · `current` (GET)      |
| `api/admin.php`       | GET: `dashboard`, `stats`, `integrations`, `users`, `user_detail`, `ads`, `ad_detail`, `categories`, `attributes`, `reviews`, `audit`, `export_users`, `export_ads` · GET: `security`, `ip_bans`, `legal` · POST: `user_ban` (причина обязательна), `user_unban`, `ip_ban_add`, `ip_ban_delete`, `legal_save`, `settings_save`, `user_block`, `user_unblock`, `user_password`, `user_role`, `user_delete`, `ad_moderate`, `ad_delete`, `ads_bulk`, `category_create/update/delete`, `attribute_save/delete`, `review_delete` |

Коды: `401` — нужен вход, `403` — нет прав, `404` — не найдено, `419` — устарел CSRF-токен, `422` — ошибки валидации по полям, `429` — слишком часто.

## Безопасность

- **SQL**: только PDO prepared statements (`ATTR_EMULATE_PREPARES = false`), `ILIKE` экранируется, `ORDER BY` — по белому списку, фильтры по характеристикам — через параметры JSONB.
- **Пароли**: `password_hash` / `password_verify`, автоматический rehash; аккаунты, созданные через Яндекс/Google, пароля не имеют.
- **Сессии**: `HttpOnly`, `SameSite=Lax`, `Secure` за HTTPS-прокси, `use_strict_mode`, `session_regenerate_id` при входе. Пользователь перечитывается из БД на каждый запрос — блокировка действует мгновенно.
- **CSRF**: токен в сессии → `<meta name="csrf-token">` → заголовок `X-CSRF-Token` на всех POST.
- **Права**: проверка на каждом эндпоинте (`Auth::requireLogin`, `Auth::requireAdmin`); владение объявлением и участие в диалоге проверяются на сервере.
- **Яндекс / Google**: PKCE (S256), одноразовый `state` в сессии со сроком 15 минут, email берётся только подтверждённый; аккаунт, созданный по email, **не захватывается** по совпадению почты — привязка только из профиля; аватар скачивается на сервер только с известных хостов по https.
- **WebSocket**: подписанный тикет (HMAC-SHA256, 90 секунд), проверка Origin, лимит размера кадров, таймаут неактивных соединений.
- **IP и баны**: `X-Forwarded-For` читается справа налево и только через доверенные прокси (`TRUSTED_PROXIES`), IPv4/IPv6 и CIDR; бан сайта не действует на администраторов с открытой сессией (нельзя «запереть» себя).
- **Согласие**: без галочки сервер отклоняет регистрацию и вход (и по email, и через Яндекс/Google), версия принятых документов хранится у пользователя.
- **Видео**: тип определяется по содержимому (сигнатуры MP4/MOV/WebM), длительность MP4/MOV проверяется по заголовку файла, имена случайные, видео привязывается только своим владельцем.
- **Чат**: ограничение 20 сообщений в минуту, текст выводится только через `textContent`.
- **Загрузки фото**: MIME по содержимому + `getimagesize`, лимит 5 МБ и 25 Мп, белый список JPG/PNG/WEBP/GIF, перекодирование GD (чистит EXIF и «приклеенный» код), случайные имена; аватары — квадрат 256×256.
- **XSS**: серверные шаблоны — `htmlspecialchars` (`e()`), клиентский JS строит DOM через `createElement`/`textContent`, `innerHTML` не используется.
- **CSV-экспорт**: ячейки, начинающиеся с `= + - @`, экранируются (защита от CSV-инъекций).
- DocumentRoot — `public/`: `src/`, `templates/`, `database/`, `docker/` и `.env` недоступны по HTTP; в `uploads/` PHP не исполняется.

## Запуск без Docker (для разработки)

Нужны PHP ≥ 8.2 с `pdo_pgsql`, `gd`, `mbstring`, `fileinfo`, `exif`, `curl` и PostgreSQL 12+ (локаль БД с поддержкой кириллицы, например `en_US.UTF-8`, — иначе регистронезависимый поиск `ILIKE` не будет учитывать регистр русских букв).

```bash
psql -U postgres -c "CREATE USER ads_user WITH PASSWORD 'ads_pass'" -c "CREATE DATABASE ads OWNER ads_user"
export DB_HOST=127.0.0.1 APP_DEBUG=1 APP_DEMO=1
php bin/migrate.php                                         # схема + демо-данные
php bin/ws-server.php &                                     # WebSocket на :8081
php -S 127.0.0.1:8080 -t public docker/php/router.php       # сайт
```

## Что проверено

Всё прогнано в браузере (Chromium/Playwright, два независимых профиля для чата) на PostgreSQL 16 и PHP 8.3:

- миграции с нуля и обновление «старой» базы; демо-данные;
- тема (переключение, сохранение между страницами и перезагрузкой), подсказки городов, избранное (в том числе гость → вход);
- счётчик просмотров: перезагрузки и повторные заходы не накручивают, второй человек +1, автор/бот не считаются, гость → вход не удваивается;
- создание объявления с характеристиками (валидация, JSONB, отображение, фильтры на главной по марке/году), статистика, профиль, аватар, смена пароля;
- отзывы (кто может, обновление вместо дубля, запреты), доступ к чужим диалогам, CSRF;
- чат: создание диалога первым сообщением, доставка и счётчики в реальном времени, «Прочитано» без перезагрузки, «печатает…», история, мобильная вёрстка,
  остановка WebSocket-сервера → опрос → автоматическое переподключение;
- вход через Яндекс и Google — **против заглушки**, повторяющей документацию провайдеров (PKCE, state, обмен кода, профиль, аватар): новый пользователь, повторный вход,
  занятая почта (без захвата аккаунта), привязка/отвязка, чужой аккаунт, отказ, подделанный state, повтор ссылки, заблокированный;
- админка: дашборд, пользователи (поиск, карточка, блокировка, роль, удаление), массовая модерация, редактор характеристик, отзывы, журнал, CSV, раздел «Интеграции»;
- согласие с политикой (регистрация, вход, OAuth), редактирование документов в админке, сохранение IP/User-Agent (включая попытку подделки `X-Forwarded-For`);
- баны: аккаунт (причина и срок, сессия обрывается, причина видна при входе по email/Яндекс/Google, истечение, снятие), бан IP на вход и на весь сайт, защита от самоблокировки админа;
- звонки (две вкладки с фейковой камерой и микрофоном): соединение, звук и видео в обе стороны (≥ 15 кадров/с, потери < 1 %, джиттер < 40 мс), микрофон и камера «на лету»,
  пинг, отказ / отмена / таймаут / занято / «не в сети», обрыв WebSocket посреди разговора, уход со страницы, две вкладки получателя, звонок со страницы объявления,
  правила «только звонок» и «только сообщения», лимит вызовов, мобильная вёрстка; отдельно — звонок строго через локальный TURN-сервер coturn;
- определение города (разрешение, отказ, ручной выбор, профиль, форма объявления), способ связи и видеообзор (загрузка, проверки, замена/удаление файла, Range-запросы, чат отключён для «только звонок»);
- адаптив 360–1440 px и светлая/тёмная тема на всех страницах без горизонтальной прокрутки, 404, robots.txt и sitemap.xml.

Не проверялось в среде разработки: сборка Docker-образов (там нет Docker — `docker compose up --build` на вашей машине будет первой реальной сборкой)
и вход через **настоящие** Яндекс и Google (нужны ваши приложения у провайдеров — после подключения проверьте вход вручную, см. [docs/OAUTH_LOGIN.md](docs/OAUTH_LOGIN.md)).

## Ограничения и что можно улучшить

- Нет защиты от перебора паролей на входе и капчи при показе телефона; нет восстановления пароля по email (письма не отправляются).
- Фото, загруженные, но так и не привязанные к объявлению (вкладку закрыли), остаются на диске — нужен cron-скрипт очистки.
- Поиск — `ILIKE`; для больших объёмов стоит добавить полнотекстовый индекс (`tsvector` + GIN).
- WebSocket-сервер — один процесс на `stream_select` (хватает на сотни одновременных подключений); для тысяч нужен отдельный масштабируемый сервис.
- Подсказки городов работают по встроенному списку; определение города по координатам идёт через публичный Nominatim (лимит ~1 запрос/сек) — для большой нагрузки нужен свой геокодер.
- Звонки видны получателю, только пока сайт открыт в браузере (для звонков при закрытой вкладке нужны Web Push и service worker); работа на реальных мобильных сетях, iPhone и за корпоративными NAT
  в этой среде не проверялась — после выкладки сделайте тестовый звонок между телефоном и компьютером (см. [docs/CALLS.md](docs/CALLS.md)).
- Видеообзор не перекодируется (в образе нет ffmpeg): длительность проверяется только у MP4/MOV, превью-кадра нет — на карточке показывается фото. Для постера и сжатия добавьте ffmpeg.
- Тексты политики и соглашения — шаблоны общего вида, они не заменяют юридическую консультацию.
- Оплата и платные услуги (продвижение, ЮKassa) не реализованы.
