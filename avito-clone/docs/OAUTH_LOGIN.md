# Вход через Яндекс и Google: где взять ключи и как подключить

На сайте два способа входа «в один клик» — **Яндекс ID** и **Google** (OAuth 2.0: код авторизации + PKCE). Вход по email и паролю остаётся.
Кнопка провайдера появляется на страницах входа и регистрации, только когда для него заданы ключи; пока ключей нет — кнопки скрыты и всё
работает как раньше. Раздел админки **«Интеграции»** показывает состояние, готовые значения для кабинетов (с кнопкой «Копировать»)
и те же шаги.

> Что проверено: весь поток (редирект → обмен кода → профиль → создание/привязка аккаунта, проверка `state`, PKCE, аватар) прогнан
> автотестами против заглушки, повторяющей документацию провайдеров. С настоящими Яндексом и Google это нужно один раз проверить
> вручную после подключения (шаг 5): у разработки не было ваших ключей.

## Два адреса, которые понадобятся в кабинетах

Для сайта `https://board.vancodex.tech` (подставьте свой домен):

| Что | Значение |
|---|---|
| **Redirect URI** (он же «Callback URI», «URI перенаправления») — один и тот же у обоих провайдеров | `https://board.vancodex.tech/oauth-callback.php` |
| Домен сайта (если спросят) | `board.vancodex.tech` |

Писать нужно **ровно так**: с `https`, без слэша на конце и без лишних символов. Google сравнивает адрес строго.

## 1. Яндекс

1. Откройте **https://oauth.yandex.ru/** под своим аккаунтом Яндекса → **«Создать приложение»** → тип **«Для авторизации пользователей»**.
2. Заполните название сервиса (его увидят пользователи), загрузите иконку (до 1 МБ), укажите контактную почту → **«Продолжить»**.
3. **Платформы:** отметьте **«Веб-сервисы»** и в поле Redirect URI вставьте `https://board.vancodex.tech/oauth-callback.php`.
4. **Доступ к данным:** отметьте логин, имя и фамилию, адрес электронной почты и портрет пользователя → **«Продолжить»** → **«Всё верно»**.
5. Откроется страница приложения: **ClientID** — это и есть ключ. **Client secret** («пароль») сайту для входа **не обязателен** (мы используем PKCE),
   но его можно ввести тоже.

Если Яндекс попросит модерацию приложения, до её прохождения вход может работать только у владельца приложения; статус виден на его странице.

## 2. Google

Названия пунктов в консоли Google иногда меняются; суть такая:

1. Откройте **https://console.cloud.google.com/auth/overview** (Google Auth Platform) под своим аккаунтом Google, создайте проект (если нет) и пройдите
   первичную настройку: название приложения, почта поддержки, аудитория **«Внешняя» (External)**, контактная почта.
2. Раздел **«Клиенты» (Clients)** → **«Создать клиент»** → тип приложения **«Веб-приложение» (Web application)**.
3. В **«Авторизованные URI перенаправления» (Authorized redirect URIs)** нажмите «Добавить URI» и вставьте `https://board.vancodex.tech/oauth-callback.php` → **«Создать»**.
4. Появятся **Client ID** и **Client secret**. Секрет показывается при создании — сохраните его (потом его можно сбросить и получить новый).
5. Раздел **«Аудитория» (Audience)** → **«Опубликовать приложение» (Publish app)**. Пока приложение в режиме «Тестирование», войти могут только добавленные
   вами тестовые пользователи (до 100). Для входа нужны только базовые права (имя, email, фото) — отдельная проверка Google для них не требуется.
6. Изменения у Google применяются не мгновенно: если сразу после настройки ошибка `redirect_uri_mismatch`, подождите 5–10 минут.

## 3. Прописать ключи на сервере

Ключи хранятся только в файле `.env` на сервере (он в `.gitignore`, в репозиторий не попадает). **Секреты не вставляйте в чаты и переписки.**

**Одной командой** (скрипт спросит ключи, ввод секретов скрыт и в историю команд не попадает, затем перезапустит сайт):

```bash
cd ~/huek/avito-clone && bash bin/setup-oauth.sh
```

Сайт за Caddy, а не за nginx на хосте: `bash bin/setup-oauth.sh --caddy`. Оставить поле пустым — значит не менять текущее значение.

**Или вручную:**

```bash
cd ~/huek/avito-clone
nano .env     # заполнить YANDEX_CLIENT_ID, YANDEX_CLIENT_SECRET, GOOGLE_CLIENT_ID, GOOGLE_CLIENT_SECRET (сохранить: Ctrl+O, Enter; выйти: Ctrl+X)
docker compose -f docker-compose.prod.yml -f docker-compose.nginx.yml up -d app ws
```

Локально (docker compose из корня проекта): те же переменные в `.env` + `APP_URL=http://localhost:8080`, затем `docker compose up -d`.
Для проверки на компьютере в кабинетах нужен Redirect URI `http://localhost:8080/oauth-callback.php` (Google разрешает `http` только для `localhost`).

## 4. Переменные окружения

| Переменная | Назначение |
|---|---|
| `YANDEX_CLIENT_ID` | ClientID приложения Яндекса. Пусто — кнопки Яндекса нет |
| `YANDEX_CLIENT_SECRET` | Client secret Яндекса (необязателен) |
| `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET` | Ключи Google. Нужны **оба**, иначе кнопки Google нет |
| `APP_URL` | Публичный адрес сайта; от него строится Redirect URI `APP_URL/oauth-callback.php`. В боевом compose по умолчанию `https://DOMAIN` |

## 5. Проверка и частые ошибки

1. Откройте `https://board.vancodex.tech/login.php` — под формой появятся кнопки **«Войти через Яндекс»** и **«Войти через Google»**.
2. Нажмите кнопку, разрешите доступ — вас вернёт на сайт уже авторизованным. Первый вход создаёт аккаунт (имя, фото и email берутся из профиля).
3. Если вернуло на страницу входа с красным сообщением или ошибка на стороне провайдера:

| Симптом | Причина |
|---|---|
| Кнопки нет | Не заданы ключи (для Google — оба) или контейнеры не перезапущены (`up -d app ws`) |
| Google: `redirect_uri_mismatch` | Адрес в кабинете не совпадает с `https://ваш-домен/oauth-callback.php` (проверьте `https`, путь, слэш на конце); после правки подождите несколько минут |
| Google: `access_denied` / «приложение не прошло проверку» | Приложение в режиме «Тестирование», а вы не в списке тестовых пользователей — опубликуйте приложение (шаг 2.5) или добавьте себя |
| Яндекс: ошибка про `redirect_uri` | Адрес не добавлен в «Веб-сервисы» → Redirect URI приложения |
| «… не выдал токен: invalid_client» | Неверный Client ID или Client secret — запустите `bin/setup-oauth.sh` ещё раз |
| «Не удалось связаться с сервисом» | Сервер не достучался до провайдера (файрвол/DNS): на сервере `curl -I https://oauth.yandex.ru` и `curl -I https://oauth2.googleapis.com` |
| «Аккаунт с почтой … уже есть на сайте» | Такая почта уже зарегистрирована обычным способом — см. раздел 6 |
| «Сессия входа истекла» | Вход шёл дольше 15 минут или в браузере выключены cookie |

Подробности ошибок — в логе: `docker compose -f docker-compose.prod.yml logs --tail=50 app`.

## 6. Как это работает для пользователей

- Первый вход через Яндекс/Google **создаёт аккаунт** (имя и фото берутся у провайдера, фото сохраняется у нас). Пароль не нужен.
- Повторный вход находит тот же аккаунт по идентификатору у провайдера — дублей не будет, даже если человек сменит почту.
- Если почта из Яндекса/Google **уже зарегистрирована на сайте обычным способом**, аккаунты автоматически не объединяются и новый не создаётся
  (на сайте нет подтверждения email — иначе чужую почту можно было бы «зарегистрировать» заранее и потом перехватить аккаунт).
  Человек увидит сообщение; нужно войти по email и паролю и нажать **«Привязать»** в «Профиле».
- Один аккаунт Яндекса/Google привязывается только к одному профилю; к профилю — не больше одного аккаунта каждого провайдера.
- «Отвязать» доступно, только если останется другой способ войти (пароль с email или другой привязанный аккаунт).
- В админке («Пользователи») видно, кто вошёл через какую соцсеть; есть фильтр «Вошли через Яндекс/Google».

## Согласие с политикой

Кнопки «Войти через Яндекс / Google» работают только после того, как посетитель отметил галочку согласия с Политикой обработки персональных данных и Пользовательским соглашением (она находится на страницах входа и регистрации). Тексты документов и реквизиты оператора редактируются в админке: «Документы».

Заблокированному пользователю (аккаунт или IP) вход через Яндекс/Google тоже закрыт — после проверки учётных данных он увидит причину и срок блокировки.
