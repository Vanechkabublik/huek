# Вход через VK: где взять ключи и как подключить

На сайте реализован вход через **VK ID** (OAuth 2.1: код авторизации + PKCE). Нужен только **ID приложения**
(`client_id`) — секретный ключ не требуется, поэтому в репозитории и на сервере нечего «красть».
Пока `VK_CLIENT_ID` не задан, кнопки «Войти через VK» на сайте просто скрыты.

> Что проверено: весь поток (редирект → обмен кода → профиль → создание/привязка аккаунта, проверка `state`, PKCE) прогнан
> автотестами против заглушки, повторяющей документацию VK ID. С настоящим VK это нужно один раз проверить вручную после
> подключения (шаг 5) — у разработки не было вашего приложения VK.

## 1. Кабинет VK ID

1. Откройте **https://id.vk.ru/about/business/go** (кабинет VK ID для бизнеса; адрес id.vk.com ведёт туда же) и войдите своим аккаунтом VK.
   Если попросят — создайте профиль бизнеса (это бесплатно; нужен для доступа к настройкам приложений).
2. Раздел **«Мои приложения» → «Добавить приложение»**.
3. Заполните форму:

   | Поле | Что указать |
   |---|---|
   | Название | Видят пользователи в окне входа, например `Авито-клон` |
   | Платформа | **Web** |
   | Иконка / изображение | Любая картинка (требует форма) |
   | **Базовый домен** | Только домен, без `https://` и пути: `board.vancodex.tech` |
   | **Доверенный Redirect URL** | `https://board.vancodex.tech/vk-callback.php` — **ровно так**, с `https` и путём |

   Домен в Redirect URL должен совпадать с базовым доменом, включая регистр. Для проверки на своём компьютере можно
   создать второе приложение с базовым доменом `localhost` и Redirect URL `http://localhost:8080/vk-callback.php`.
4. Нажмите **«Создать приложение»**.

## 2. Где лежит ID приложения

Карточка приложения → раздел **«Приложение» → «Информация о приложении»** → поле **ID приложения** (число, например
`51234567`). Это и есть `VK_CLIENT_ID`.

«Защищённый ключ» и «Сервисный ключ доступа» из этой же страницы **сайту не нужны** — никому их не показывайте и не
вставляйте ни в чат, ни в репозиторий.

## 3. Прописать ID на сервере

Настройки живут только в файле `.env` на сервере (он в `.gitignore`, в репозиторий не попадает).

**Одной командой** (подставьте свой ID — это число, не секрет):

```bash
cd ~/huek/avito-clone && VK_CLIENT_ID=51234567 bash bin/server-update.sh
```

Скрипт запишет ID в `.env`, пересоберёт контейнеры и перезапустит их.

**Или вручную:**

```bash
cd ~/huek/avito-clone
nano .env                       # строка VK_CLIENT_ID=51234567  (сохранить: Ctrl+O, Enter, выйти: Ctrl+X)
docker compose -f docker-compose.prod.yml -f docker-compose.nginx.yml up -d app ws
```

(Если сайт запущен через Caddy, а не nginx на хосте: `docker compose -f docker-compose.prod.yml up -d app ws`.)

Локально (docker compose из корня проекта): добавьте в `.env` `VK_CLIENT_ID=…` и `APP_URL=http://localhost:8080`,
затем `docker compose up -d`.

## 4. Переменные окружения

| Переменная | Назначение | По умолчанию |
|---|---|---|
| `VK_CLIENT_ID` | ID приложения VK ID. Пусто — вход через VK выключен | — |
| `APP_URL` | Публичный адрес сайта; из него строится Redirect URL `APP_URL/vk-callback.php` | `https://DOMAIN` (в prod-compose) |
| `VK_SCOPE` | Какие данные запрашивать у VK | `vkid.personal_info` (имя, фамилия, фото) |
| `VK_ID_BASE` | Адрес VK ID (нужен в тестах с заглушкой) | `https://id.vk.ru` |

Хотите получать ещё и email — задайте `VK_SCOPE="vkid.personal_info email"` (в приложении VK ID должен быть доступен
доступ к email). Без email всё работает: у аккаунта просто не будет почты, её можно добавить в «Профиле».

## 5. Проверка

1. Откройте `https://board.vancodex.tech/login.php` — под формой должна появиться синяя кнопка **«Войти через VK»**.
2. Нажмите её, разрешите доступ — вас вернёт на сайт уже авторизованным.
3. Если вернуло на страницу входа с красным сообщением — смотрите таблицу ниже и лог:
   `docker compose -f docker-compose.prod.yml logs --tail=50 app`.

| Сообщение / симптом | Причина |
|---|---|
| Кнопки VK нет | Не задан `VK_CLIENT_ID` или контейнеры не перезапущены (`up -d app`) |
| Ошибка на стороне VK про `redirect_uri` | Redirect URL в кабинете не совпадает с `https://ваш-домен/vk-callback.php` (проверьте `https`, путь, отсутствие `/` в конце и базовый домен) |
| «VK не выдал токен: …» | Текст ошибки от VK; обычно неверный `VK_CLIENT_ID` или приложение не опубликовано/отключено в кабинете |
| «Не удалось связаться с VK» | Сервер не достучался до `id.vk.ru` (файрвол/DNS). Проверка: `curl -I https://id.vk.ru` на сервере |
| «Сессия входа через VK истекла» | Вход шёл дольше 15 минут или закрыты cookie |

## 6. Как это работает для пользователей

- Первый вход через VK **создаёт аккаунт** (имя и фото берутся из VK). Пароль не нужен.
- Повторный вход находит тот же аккаунт по VK ID — дублей не будет.
- Аккаунт, зарегистрированный по email, **не захватывается автоматически** по совпадению почты: привязать VK можно только
  из «Профиля» после входа по паролю (кнопка «Привязать VK»). Так чужой VK-аккаунт с вашей почтой не получит доступ.
- VK, уже привязанный к одному аккаунту, нельзя привязать ко второму.
- «Отвязать VK» доступно, только если у аккаунта есть email и пароль (иначе человек потеряет доступ).
- Вход по email и паролю остаётся (для администратора и тех, кто не хочет VK).
